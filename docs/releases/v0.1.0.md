# MooNsEvents v0.1.0 — public evaluation release

Status: **prepared; publish after the release pull request is merged into `main`.**

## What this release is for

Version 0.1.0 gives events operators, developers, and contributors a stable point from which to
evaluate MooNsEvents locally. It focuses on the connected client workflow rather than claiming
that every optional provider integration is ready for production.

## Evaluate this path

1. Capture and manage a lead.
2. Curate a package and day-by-day runOfShow.
3. Build or export its production timeline.
4. Select suppliers and review an RFQ.
5. Prepare a proposal and move accepted work toward booking and operations.
6. Inspect Maya's channel, tool, and approval guardrails.

## Included

- Events CRM, leads, follow-ups, proposals, bookings, and operational views
- Package, run-of-show, vendor, stay, car, activity, and media workspaces
- RFQ composition, vendor selection, outreach history, and response-processing surfaces
- Team/customer support chat and a human-operated lead WhatsApp inbox
- Maya voice/chat/inventory/operations integration surfaces with approval and kill-switch controls
- Multi-tenant platform architecture, workers, audit paths, and local Docker launchers
- Product showcase, capability-status matrix, production checklist, and performance evidence policy

## Known limitations

- The project is ready for local use, evaluation, development, and controlled pilots. Production
  deployments handling real customer or payment data must complete the readiness checklist.
- AI, email, telephony, WhatsApp, payments, SSO, object storage, live timeline data, and inventory
  providers require accounts and credentials owned by the operator.
- Missing providers remain disabled or fail closed; the repository contains no shared provider
  credentials.
- The desktop installer discussed on the roadmap is not part of this release.
- No production throughput, uptime, adoption, or customer-impact claim is made.
